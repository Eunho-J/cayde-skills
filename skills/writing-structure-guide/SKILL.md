# 글의 구성과 집필

## 1. 목적과 독자에 맞춰 재료를 고른다

1. 먼저 사용자가 원하는 일이 **틀의 목록 보기, 틀 비교, 새 글의 개요 짜기, 기존 글 진단·재구성, 실제 집필** 중 무엇인지 구별한다. 요청한 범위만 수행한다.
2. 글의 목적, 예상 독자, 장르·매체, 분량, 핵심 메시지, 필수 소재 및 형식 제약을 확인한다. 이미 주어진 정보는 다시 묻지 않는다. 불명확해도 가능한 범위에서 진행하고 선택을 뒤집을 만한 정보만 질문한다.
3. 기존 글을 고칠 때는 먼저 단락마다 한 줄로 기능을 적는 **역개요**를 만든 뒤 중복·비약·누락을 진단한다. 글을 다시 쓸지 여부는 사용자의 요청에 따른다.
4. 한국어 결과물은 완전한 문장으로 쓴다. 비교 차트와 빠른 개요에는 짧은 구절을 써도 된다. 구조의 단계 수나 순서를 절대 법칙, 문화권 전체의 보편 법칙으로 소개하지 않는다.

구성 틀, 섹션, 문단, 실제 문장 순으로 범위를 좁혀 작업하고, 각 단계의 검수를 통과한 뒤에 다음으로 넘어간다. 검수는 자체적으로 수행하되, 사용자가 단계별 확인이나 `다음` 승인을 요구했다면 해당 경계에서 멈춘다. 문제가 상위 구성에 있으면 그 단계로 돌아가 고친다.

중심 질문과 독자가 도달할 생각을 정한 뒤, 그 사이를 설명하는 데 필요한 재료만 고른다. 각 자료에서 무엇을 확인했는지, 어떤 주장이나 장면에 쓸 것인지, 그 자료가 없으면 어떤 설명이 부족해지는지 판단한다. 자료의 목록이나 조사 순서를 그대로 목차로 옮기지 않는다.

참조한 문서의 모든 내용을 담으려 하지 않는다. 읽어 둔 연구, 흥미로운 사실, 예상 가능한 예외라도 현재의 설명을 진전시키지 않으면 쓰지 않는다. 조사량이 늘었다는 이유로 글을 늘리지 않는다. 필요한 설명의 범위를 기준으로 분량을 정하고, 덜어 낼 때에도 독자가 이해하는 데 필요한 관계는 남긴다. 목록이나 전수조사가 요청되었다면 정해진 범위는 빠짐없이 충족한다.

### 재료 선별 검수

중심 질문, 독자, 목표 분량을 기준으로 자료의 사용처를 확인한다. ‘주제와 관련 있다’거나 ‘조사한 내용을 보여주고 싶다’는 이유만 남는 자료는 집필 재료에서 뺀다. 결론을 바꾸는 반증이나 주장의 성립 조건은 남기고, 확인되지 않은 핵심 근거는 검증하거나 주장의 범위를 줄인다. 무엇을 설명하고 무엇을 덜어 낼지 정한 뒤 구성 틀을 고른다.

## 2. 독자가 따라갈 전체 구조를 고른다

아래 트리에서 **전체 글의 주된 구조 하나**를 먼저 고른다. 필요하다면 시간·공간·중요도 등의 **배열 방식**과 문단·도입부의 **국소적 틀**을 결합한다. 장르, 글 전체 구조, 재료의 배열 방식, 문단 구조를 같은 층위의 대안처럼 나열하지 않는다.

추천할 때는 보통 적합한 틀 2~3개에 한정해, **이 글에서 얻는 이점과 감수할 한계**를 각각 설명한다. 사용자가 틀 전체를 요청했을 때만 차트 전부를 보여준다. 틀을 기계적으로 강요하지 않고 과제 지시와 분야 관습을 우선한다.

### 분류 트리

아래는 **목적별 선택 트리**다. 한 글은 `주된 구조 + 배열 방식 + 국소적 틀`을 동시에 가질 수 있다.

```text
글을 통해 무엇을 하려는가?
├─ 사건·변화를 경험시키기 → 서사
│  ├─ 간결한 전환과 마무리 → 기승전결
│  ├─ 목표·갈등·해결 → 3막 구조
│  ├─ 갈등의 상승과 하강 → 5단계 극적 곡선
│  ├─ 인물의 출발·시련·귀환 → 영웅의 여정 / 스토리 서클
│  └─ 상세한 장면·전환점 설계 → 세이브 더 캣 / 7점 구조
├─ 정보를 이해시키기 → 설명·분석
│  ├─ 기본적인 논의의 틀 → 서론–본론–결론
│  ├─ 답을 빨리 전달 → 두괄식 / 피라미드 구조
│  ├─ 변화·경과를 추적 → 연대기
│  ├─ 원인을 규명 → 원인–결과
│  ├─ 선택지를 평가 → 비교·대조 (대상별 / 기준별)
│  ├─ 복잡한 대상을 나누어 이해 → 분류·구획
│  ├─ 절차를 재현 → 과정·단계 설명
│  └─ 문제를 진단하고 제안 → 문제–원인–해결 / SCQA
├─ 주장을 검토·설득하기 → 논증
│  ├─ 빠른 답변·짧은 주장 → PREP
│  ├─ 근거와 전제를 엄밀히 점검 → 툴민 논증
│  ├─ 찬반과 반론을 정면으로 다룸 → 고전적 논증
│  └─ 대립하는 독자와 공통점 찾기 → 로저리언 논증
├─ 특정 행동을 요청하기 → 행동 유도
│  ├─ 홍보·판매 메시지 → AIDA / PAS
│  └─ 행동 촉구 연설·제안 → 먼로의 동기화 순서
└─ 정해진 장르 관습에 맞추기 → 보도·연구
   ├─ 뉴스·긴급 공지 → 역피라미드
   ├─ 실증 연구 보고 → IMRaD
   └─ 연구 서론의 필요성 제시 → CARS

선택한 구조 안에서 재료를 어떤 순서로 보여줄까? → 시간순 / 역순·중간 시작 / 공간순 / 중요도순
문단 하나를 어떻게 전개할까? → 주장–근거–해설 / PREP
```

**주의:** 기승전결의 `전`은 관점·상황의 전환이지 반드시 적과의 충돌이나 충격적 반전은 아니다. `갈등이 없는 이야기`라고 단정하지 않는다. `연대기`는 글 전체를 경과 중심으로 짜는 방식이고 `시간순`은 한 부분의 재료를 배열할 때에도 쓸 수 있다. 다섯 단락짜리 글은 교육용 발판일 수 있지만 모든 글의 표준 분량이나 최적 형태는 아니다.

### 틀별 선택 차트

각 행의 장점·한계는 **실무적 판단 기준**이다. 개별 작품에서의 효과를 보장한다는 뜻이 아니다.

#### 1. 서사 구조

| 틀과 흐름 | 언제 쓰면 좋은가 | 장점 | 한계·피할 상황 |
|---|---|---|---|
| **기승전결**: 제시 → 확장 → 전환 → 수습. | 짧은 이야기, 칼럼, 4컷 구성에서 관점의 전환을 만들 때. | 갈등을 반드시 전제로 삼지 않고 대비와 재해석을 설계할 수 있다. | 전환만 억지로 넣으면 앞부분과 결말의 연결이 약해진다. 긴 서사의 장면별 설계에는 거칠다. |
| **3막 구조**: 설정 → 대립·진전 → 해결. | 주인공의 목표와 장애가 선명한 극·소설·영상물을 설계할 때. | 큰 전환점과 결말의 방향을 잡기 쉽다. | 사건을 정해진 비율에 맞추면 인물·주제가 도식화될 수 있다. |
| **5단계 극적 곡선**: 발단 → 상승 → 절정 → 하강 → 결말. | 갈등의 고조와 절정 이후의 여파를 점검할 때. | 긴장도의 상승뿐 아니라 결과가 정리되는 구간도 보게 한다. | 절정이 여러 번이거나 병렬적인 이야기에는 단일 산 모양이 맞지 않을 수 있다. |
| **영웅의 여정**: 출발 → 시련·변화 → 귀환. | 한 인물의 내적 변화와 낯선 세계로의 이동이 중심일 때. | 외부 사건과 성장의 관계를 점검하기 좋다. | 모든 단계나 멘토·귀환을 의무화하면 작품의 고유한 형태를 해친다. |
| **스토리 서클**: 익숙한 곳 → 욕구 → 낯선 곳 → 적응 → 획득 → 대가 → 귀환 → 변화. | 캐릭터의 욕구·대가·변화를 짧은 에피소드 단위로 추적할 때. | 시작과 끝의 인물 상태를 비교하기 쉽다. | 주인공의 욕구가 약하거나 집단 서사라면 중심축을 하나로 좁히기 어렵다. |
| **세이브 더 캣 비트시트**: 시작·중간·끝을 15개 전환점으로 세분. | 장편 상업 서사에서 전개 속도와 주요 비트를 촘촘히 설계할 때. | 빠진 전환점과 중반의 정체를 찾아내기 쉽다. | 비트를 모두 채우는 데 집중하면 예측 가능한 전개가 될 수 있다. |
| **7점 구조**: 시작, 두 전환점, 두 압박, 중점, 결말. | 시작과 끝의 대비를 먼저 정하고 사건의 압박을 배치할 때. | 결말에서 역산해 인물과 사건의 변화를 설계하기 좋다. | 세부 장면의 정서와 목소리는 별도로 만들어야 한다. |

#### 2. 설명·분석 구조

| 틀과 흐름 | 언제 쓰면 좋은가 | 장점 | 한계·피할 상황 |
|---|---|---|---|
| **서론–본론–결론**: 주제·질문 → 전개 → 정리. | 과제, 설명문, 긴 글에서 기본적인 독서 경로를 만들 때. | 독자가 글의 시작·전개·도착점을 파악하기 쉽다. | 세 부분의 이름만 정하면 실제 논리와 문단 간 연결이 생기지 않는다. `본론 세 문단`은 필수가 아니다. |
| **두괄식**: 결론·핵심 → 근거·세부. | 바쁜 독자에게 메모, 이메일, 보고서의 답을 빨리 전달할 때. | 결론을 놓칠 위험이 적다. | 발견의 과정이나 서스펜스가 중요한 글에서는 효과가 줄 수 있다. |
| **미괄식**: 관찰·근거 → 결론. | 독자가 결론에 이르는 추론 자체를 경험해야 할 때. | 근거가 누적되면서 통찰을 만들어낼 수 있다. | 독자가 빨리 답을 찾아야 할 때는 비효율적이다. 결론을 숨기기만 하면 답답하다. |
| **피라미드 구조**: 핵심 답 → 묶인 하위 주장 → 증거. | 의사결정 보고서나 제안서의 여러 근거를 계층화할 때. | 주장 간의 상하 관계와 누락을 점검하기 쉽다. | 질문이 열려 있거나 탐색 자체가 목적인 글에는 너무 일찍 결론을 고정할 수 있다. |
| **연대기**: 먼저 일어난 일 → 나중에 일어난 일. | 역사, 사건 경과, 실험·작업 기록의 변화 과정을 보여줄 때. | 시간 관계가 명확하다. | 중요한 원인이나 쟁점이 시간순에 가려질 수 있다. |
| **원인–결과**: 결과 또는 현상 → 원인·기제 → 영향. | 왜 일이 일어났는지 설명하고 여파를 분석할 때. | 단순 사건 나열을 설명으로 바꾼다. | 상관관계를 인과관계로 단정하거나 복수 원인을 누락하기 쉽다. |
| **비교·대조: 대상별**: A의 기준들 → B의 같은 기준들. | 비교 대상이 적고 각각을 먼저 온전히 이해시켜야 할 때. | 대상별 성격을 한 번에 볼 수 있다. | 독자가 같은 기준의 차이를 머릿속에서 다시 대조해야 한다. |
| **비교·대조: 기준별**: 기준 1의 A/B → 기준 2의 A/B. | 제품·정책·작품 등 선택지를 항목별로 판단할 때. | 기준마다 차이를 즉시 볼 수 있다. | 기준이 너무 많으면 글이 잘게 끊기고 전체 인상이 약해진다. |
| **분류·구획**: 대상 → 구분 기준 → 범주별 설명. | 복잡한 현상이나 개념의 종류·구성요소를 정리할 때. | 정보의 범위와 빠진 항목을 점검하기 쉽다. | 구분 기준이 흔들리거나 범주가 겹치면 오히려 혼란스럽다. |
| **과정·단계 설명**: 선행 조건 → 단계 → 결과·점검. | 사용법, 제작 절차, 업무 흐름을 재현하게 할 때. | 실행 순서와 의존성이 선명하다. | 이유·예외·실패 조건을 생략하면 따라 하기만 가능한 글이 된다. |
| **문제–원인–해결**: 문제 정의 → 원인 → 해결책·검증. | 개선안, 정책 제안, 진단 보고를 쓸 때. | 해법이 무엇을 해결하는지 연결하기 쉽다. | 문제를 단정하거나 증거 없이 해결책부터 정하면 설득력이 떨어진다. |
| **SCQA**: 상황 → 복잡화/문제 → 독자의 질문 → 답. | 배경을 공유한 독자에게 ‘왜 지금 이 답이 필요한가’를 설명할 때. | 답이 겨냥하는 질문을 분명히 한다. | 문제와 질문을 억지로 만들면 짧은 사실 전달에는 장황하다. 원전의 `SCQ`에 답을 붙인 실무적 표기다. |

#### 3. 논증과 행동 유도

| 틀과 흐름 | 언제 쓰면 좋은가 | 장점 | 한계·피할 상황 |
|---|---|---|---|
| **PREP**: 주장 → 이유 → 예시 → 주장 재확인. | 짧은 답변, 발언, 한 문단짜리 주장에 집중할 때. | 즉석에서 핵심 메시지를 빠르게 정리한다. | 긴 글에서 반복하면 같은 결론을 되풀이하기 쉽고 반론 처리도 약하다. |
| **툴민 논증**: 주장 → 근거 → 근거와 주장을 잇는 전제 → 보강·한정·반론. | 근거의 타당성이나 숨은 가정을 점검해야 할 때. | ‘증거가 왜 이 결론을 뒷받침하는가’를 드러낸다. | 분석 요소가 많아 짧은 홍보문이나 감상문에는 과하다. **논증의 분석 모델이지 고정된 문단 순서가 아니다.** |
| **고전적 논증**: 도입 → 배경 → 주장 → 입증 → 반박 → 맺음. | 쟁점과 반론이 분명한 정식 논설·연설에 적합하다. | 근거 제시와 반론 대응의 자리를 확보한다. | 맥락이 이미 알려진 독자에게 배경 설명이 길어질 수 있다. |
| **로저리언 논증**: 쟁점 → 상대 관점·타당한 조건 → 내 입장 → 접점·이익. | 첨예한 의견 차이 속에서 대화 가능성을 열 때. | 상대의 우려를 공정하게 다룬다. | 명백한 허위 주장까지 대칭적인 타당성을 부여해서는 안 된다. 절충이 불가능한 사안에는 맞지 않을 수 있다. |
| **AIDA**: 주목 → 흥미 → 욕구 → 행동. | 광고·랜딩 페이지처럼 하나의 전환 행동을 요청할 때. | 독자가 행동으로 가기까지의 관심 단계를 점검한다. | 사실 확인과 충분한 설명이 중요한 글에 과도하게 적용하면 조작적으로 보인다. |
| **PAS**: 문제 → 문제의 불편·손실 부각 → 해결책. | 독자가 이미 겪는 문제를 짧은 카피에서 짚을 때. | 해결책의 필요를 빠르게 선명하게 한다. | 불안이나 고통을 과장하면 신뢰를 해친다. 문제를 느끼지 않는 독자에게는 맞지 않는다. |
| **먼로의 동기화 순서**: 주목 → 필요 → 해결 → 결과 상상 → 행동. | 청중에게 구체적 행동을 부탁하는 설득 연설·캠페인에 적합하다. | 문제와 해결을 청중의 행동까지 연결한다. | 즉각적인 행동 요구가 없는 분석문에는 부자연스럽다. |

#### 4. 장르 관습과 배열·국소 틀

| 틀과 흐름 | 언제 쓰면 좋은가 | 장점 | 한계·피할 상황 |
|---|---|---|---|
| **역피라미드**: 가장 중요한 확인 사실 → 보충 사실 → 배경. | 뉴스 기사, 속보, 사건 공지에서 핵심을 먼저 알려야 할 때. | 앞부분만 읽어도 핵심을 알 수 있다. | 인물의 체험이나 반전이 중요한 서사에는 맞지 않는다. |
| **IMRaD**: 서론 → 방법 → 결과 → 논의. | 실증 연구 결과를 재현 가능하게 보고할 때. | 연구 질문·절차·발견·해석을 구분한다. | 인문학 논평, 미래 제안, 탐색적 글에는 다른 관습이 나을 수 있다. |
| **CARS**: 연구 영역 설정 → 빈틈 제시 → 그 빈틈을 메우는 연구 제시. | 학술 논문의 **서론**에서 연구 필요성을 설명할 때. | 선행연구와 새 연구의 관계를 드러낸다. | 글 전체의 구조로 사용하면 안 된다. 억지 ‘연구 공백’ 만들기를 경계한다. |
| **시간순**: 발생 순서대로 재료를 배열. | 경과를 오해 없이 따라가야 할 때. | 전후 관계가 명확하다. | 핵심 원인이나 중요도가 시간순에 가려질 수 있다. **전체 구조 위에 얹는 배열 원칙**이다. |
| **공간순**: 위치·시선의 이동을 따라 배열. | 장소·시각 자료·물리적 구조를 안내할 때. | 독자가 동선을 상상하기 쉽다. | 장소 간 관계보다 논점이 중요하면 설명이 산만해진다. **배열 원칙**이다. |
| **중요도순**: 중요한 것부터 또는 덜 중요한 것부터 배열. | 여러 근거와 항목의 우선순위를 알려야 할 때. | 중요도 판단을 돕는다. | 중요도의 기준이 없으면 자의적으로 보인다. **배열 원칙**이다. |
| **역순 전개**: 결과에서 출발해 이전 사건을 거슬러 보여준다. | 결과가 생긴 이유를 역추적하는 이야기나 분석에 쓴다. | 이미 알려진 결과의 원인을 질문으로 만들 수 있다. | 시간 단서가 부족하면 인과를 거꾸로 이해할 수 있다. **정보 공개 순서**다. |
| **중간 시작(in medias res)**: 진행 중인 장면에서 시작하고 앞선 맥락을 나중에 제공. | 도입부에서 이미 움직이는 사건을 보여줄 때. | 설명으로 시작하지 않고 즉시 장면에 들어갈 수 있다. | 누가 어디서 무엇을 하는지 너무 늦게 알리면 혼란스럽다. **도입 기법이지 글 전체의 구조가 아니다.** |
| **주장–근거–해설**: 소주장 → 구체적 근거 → 근거의 의미·상위 주장과 연결. | 논증 글의 개별 문단에서 자료와 결론을 이어줄 때. | 인용·사례만 던져 놓는 문제를 줄인다. | 문단마다 똑같은 문장 틀을 쓰면 기계적이다. **문단 수준의 틀**이다. |

### 적용 예시

- “새 서비스 도입 여부를 임원에게 1쪽으로 설명해 줘”라면 **피라미드 구조**를 주된 틀로, 내부에 **문제–원인–해결**을 넣는다. 첫 문장에서 권고안을 말하고, 세부 근거를 그 아래에 묶는다.
- “인물의 일상에 다른 관점이 끼어드는 4컷을 짜 줘”라면 **기승전결**을 택한다. `전`에서 새로운 관점을 도입하고 `결`에서 앞 장면과의 관계를 회수한다.
- “두 도구 중 무엇을 쓸지 비교해 줘”라면 **기준별 비교·대조**를 택한다. 비용·사용성·제약 등 동일한 기준을 두 대상에 모두 적용한다.
- “주장에 근거가 있는데도 설득력이 약해”라면 문단을 **툴민의 주장–근거–전제**로 점검한다. 숨은 전제와 반론을 드러내되 원고 전체를 억지로 툴민의 여섯 부분에 맞추지는 않는다.

### 구성 틀 검수

선택한 틀이 글의 목적과 독자의 읽는 방식에 맞는지 확인한다. 글 전체의 구조, 재료를 배열하는 순서, 개별 문단의 전개 방식이 뒤섞이지 않았는지 살핀다. 틀의 칸을 채우기 위해 불필요한 소재를 추가하지 않는다. 사용할 구조와 그 안에서 논의를 발전시킬 방향을 정했으면 섹션을 설계한다.

## 3. 섹션마다 독자가 따라갈 질문을 정한다

선택한 틀에 맞춰 글의 시작과 도착점을 잡고, 그 사이에서 독자가 알아야 할 내용을 섹션으로 나눈다. 섹션은 같은 상황이나 문제를 따라가는 하나의 씬이다. 자료의 분류명이 아니라, 이 부분을 읽고 무엇을 새롭게 이해하게 되는지를 중심으로 묶는다.

개요 요청에는 각 부분의 **역할, 담을 핵심 내용, 필요한 근거 또는 장면, 다음 부분으로 넘어가는 이유**를 적는다. 실제 자료가 없으면 사실이나 출처를 지어내지 않고 `[근거 필요]`로 표시한다.

섹션 계획에는 다음 내용을 적는다.

- **시작 상태:** 독자가 이미 아는 내용과 아직 풀리지 않은 질문.
- **맡은 역할:** 그 질문에 답하기 위해 이번 섹션에서 설명하거나 경험시킬 내용.
- **필요한 재료:** 설명에 쓸 사례·장면·근거와 각각을 쓰는 이유.
- **도착 상태:** 읽은 뒤 달라질 이해·판단·정서와 그때 생기는 다음 질문.
- **분량:** 해당 역할에 필요한 설명의 범위와 전체 글에서 차지할 비중.

앞 섹션에서 생긴 질문이나 결과가 다음 섹션의 출발점이 되도록 배열한다. 칼럼에서는 중심 생각을 초반에 드러내고, 결말이 도입의 질문이나 장면을 발전된 이해로 회수하게 한다. ‘다음으로 다른 문제를 살펴보자’는 예고만 붙여 이동의 이유를 대신하지 않는다.

### 섹션 검수

1. 섹션의 시작 상태와 도착 상태를 이어 읽는다. 다음 섹션이 왜 필요한지 설명할 수 없으면 순서나 역할을 다시 정한다.
2. 한 섹션을 빼고 전체 개요를 읽는다. 필요한 설명·근거·정서적 기능이 사라지지 않고 흐름이 좋아지면 삭제한다. 자료를 조사했다는 사실은 남길 이유가 아니다.
3. 전개가 방향을 바꾸는 부분을 확인한다. 앞의 관찰이 새 질문이나 반론을 요구하고 이후의 전개가 그 변화를 이어가면 필요한 변곡이다. 앞에서 준비되지 않고 뒤에서도 역할을 하지 않는 별개의 이야기는 아웃라이어다. 필요한 내용은 재배치하고, 불필요한 내용은 과감하게 지운다.
4. 삭제 때문에 중요한 반증이나 주장의 성립 조건이 감춰지지 않았는지 확인한다. 그런 내용이 필요하다면 글의 주장과 구성을 고친다.

**진행 조건:** 각 섹션의 필요성과 이동 이유가 설명되고, 불필요한 섹션이 제거되었을 때 문단 구성으로 넘어간다. 필수 근거가 부족하면 확인하거나 주장의 범위를 줄인다.

## 4. 섹션 안에서 문단의 시선을 이어간다

섹션이 씬이라면 문단은 그 안에서 시선을 옮기는 컷이다. 문단이 달라졌다는 이유로 곧바로 다른 주제를 꺼내지 않는다. 같은 대상의 세부를 보거나, 앞서 제시한 조건을 바꾸거나, 관찰에서 이유로 이동하면서 주제를 완만하게 발전시킨다.

문단마다 다음 네 가지를 적는다.

- **이어받는 것:** 앞 문단에서 남은 질문, 대상, 상황.
- **새로 보이는 것:** 이번 문단이 추가할 관찰이나 설명, 독자의 이해가 달라지는 지점.
- **보여줄 재료:** 그 변화를 만들 사례·장면·근거와 해당 재료의 역할.
- **뒤로 넘기는 것:** 다음 문단이 받아야 할 질문이나 이해.

문단을 ‘논문 한 편’이나 ‘논거 하나’를 넣는 칸으로 만들지 않는다. 연구와 사례는 진행 중인 설명에 필요한 자리에 놓는다. 새로운 개념이나 사례를 소개할 때에도 앞에서 다루던 문제 때문에 그것이 필요해졌는지 확인한다.

예를 들어 ‘접속 기록 삭제’라는 이름만 읽은 상태에서 출발해, 실제 삭제 조건을 풀어 보고, 설명을 안 뒤 같은 짧은 이름으로 돌아오게 할 수 있다. 그러면 설명을 모르는 독자가 무엇을 복원하지 못하는지까지 같은 대상을 통해 살필 수 있다. 마지막에는 빠진 관계를 적어야 한다는 수정 기준에 도달한다. 각 문단이 다른 자료를 소개하는 대신 앞 문단에서 보던 것의 의미를 조금씩 바꾸는 전개다.

완만한 변화는 같은 말을 반복하거나 빈 연결 문단을 늘리는 일이 아니다. 한 사례를 모든 글에 고정하거나 모든 문단에 같은 형식을 강요하지도 않는다. PREP나 주장–근거–해설은 필요한 문단에서만 사용한다.

### 문단 구성 검수

1. 이웃한 두 문단의 계획을 함께 읽는다. 뒤 문단이 앞에서 생긴 질문을 받는지, 독자를 다른 이야기의 출발점으로 옮기는지 확인한다.
2. 대상·상황·논점·평가 기준이 한꺼번에 바뀌는 곳을 찾는다. 이동에 필요한 전제가 없으면 문단을 재배치·통합하거나 삭제한다.
3. ‘또한’, ‘반면’, ‘같은 이유로’ 같은 접속어 없이도 내용 사이의 관계가 성립하는지 확인한다. 공통 키워드를 썼다는 사실만으로 연결되었다고 판단하지 않는다.
4. 각 문단을 잠시 빼고 앞뒤를 잇는다. 새 이해를 만들지 않고 반복하거나 잠시 다른 화제로 샜다가 돌아오는 문단은 삭제한다. 삭제한 분량을 다른 소재로 채우지 않는다.

**진행 조건:** 각 문단이 앞에서 무엇을 받아 무엇을 더하는지 분명하고, 섹션 안에서 독자의 시선이 이어질 때 집필한다. 통과하지 못하면 연결 문장을 쓰기 전에 문단 배치를 고친다.

## 5. 계획한 변화를 실제 문장으로 쓴다

문단 계획을 문장으로 옮기되, 계획의 순서나 검수 용어를 본문에 그대로 노출하지 않는다. 독자는 개요의 칸을 보는 대신 설명과 장면을 따라가야 한다. 한국어 문장은 주어 또는 화제를 앞에서 잡고, 그 대상에 관해 무엇을 말하는지 끝까지 서술한다.

행위나 과정을 설명할 때에는 이해에 필요한 주체·대상·조건·처리·기준·결과를 적는다. ‘관리한다’, ‘반영한다’, ‘지원한다’, ‘구분한다’에서 설명을 멈추지 않고, 무엇을 어떤 기준으로 어떻게 하며 이후 무엇이 달라지는지 쓴다. 모든 문단에 이 항목들을 기계적으로 채우지는 않는다. 독자가 대신 만들어 넣어야 하는 핵심 관계를 찾아 보충한다.

‘관리를 수행한다’를 ‘관리한다’로 줄이면 표현은 짧아지지만 대상과 기준은 드러나지 않는다. ‘시스템은 대기 중인 작업을 우선순위가 높은 순서로 다시 배열한다’라고 쓰면 처리 대상과 방식이 드러난다. 표현을 간결하게 고치는 일과 설명의 빈칸을 채우는 일을 구별한다.

주장이나 해석을 쓸 때에는 근거와 이유가 어떻게 그 생각으로 이어지는지 설명한다. 확인된 사실·인용과 글쓴이의 해석·제안을 구별하고, 출처·연구 결과·개인 경험을 지어내지 않는다. 구체적인 설계나 예문이 필요하면 내용과 선택 기준을 제시하되 이미 확인된 사실이나 합의인 것처럼 쓰지 않는다. 인용은 원문의 의미를 보존하고 출처와 범위를 밝힌다.

연구를 비교할 때에는 누가 무엇을 읽고 어떤 과제를 수행했으며 무엇을 측정했는지 확인한다. 회상과 읽기시간처럼 다른 결과를 막연한 ‘가독성’으로 묶어 찬반 증거처럼 맞세우지 않는다. 연구가 보여 준 사실과 이 글에서 제안하는 작성 방법 사이의 연결도 설명해야 한다.

칼럼·논문·보고서에서는 글쓴이를 가리키는 ‘나·내·우리·저·저희’ 등 1인칭 대명사를 쓰지 않는다. 개인 경험 자체를 삭제하지 말고, 주어를 생략하거나 경험의 대상·사건·변화를 주어로 바꾼다. 다른 화자의 원문 인용은 임의로 고치지 않는다. 조사·해석·판단은 한 화자의 작업으로 서술하고, 초안에 대한 피드백 대화를 본문으로 옮기지 않는다.

현재 생각을 이해하는 데 필요하지 않은 반론·예외·비목표·방어 문장은 덧붙이지 않는다. 대비나 부정이 필요하다면 그것 때문에 달라지는 이해나 판단이 무엇인지 드러낸다. 명사화는 이미 설명한 내용을 압축하는 데 쓸 수 있지만, 아직 설명하지 않은 관계를 대신하는 이름으로 쓰지 않는다.

### 작성한 문단 검수

1. 문장을 읽고 무엇이 일어나는지, 무엇을 주장하는지, 이유와 기준이 무엇인지 설명해 본다. 문법적으로 완성됐어도 핵심 내용을 답할 수 없다면 필요한 설명을 보충한다.
2. 문단이 계획한 이해의 변화를 실제로 만들었는지 확인한다. 계획에 없던 곁가지, 같은 뜻의 반복, 역할 없는 문장은 삭제한다.
3. 사실·인용·해석·제안의 경계와 근거 범위를 확인한다. 자료가 뒷받침하지 않는 주장은 검증하거나 고친다.
4. 앞 문단의 끝, 현재 문단, 다음 문단의 시작을 이어 읽는다. 다음 문단이 아직 없다면 계획과 대조한다. 이번 문단만 자연스럽고 앞뒤 연결이 끊겼다면 배치나 내용부터 수정한다.

**진행 조건:** 필요한 설명이 갖춰지고 앞뒤 흐름이 이어질 때 다음 문단을 쓴다. 섹션을 완성하면 문단들을 연속해서 읽고 같은 검수를 반복한다. 상위 구성의 문제는 윤문으로 감추지 말고 해당 단계로 돌아가서 고친다.

## 6. 완성된 글에서 불필요한 부분을 걷어낸다

완성된 원고의 각 문단 옆에 ‘독자가 무엇을 새로 알거나 느끼게 되는가’를 한 줄로 적는다. 계획했던 역할이 아니라 실제로 쓰인 내용을 기준으로 역개요를 만든다. 그 줄들을 이어 읽어 섹션 안의 변화가 누적되는지, 섹션 사이에서 다음 질문이 생기는지 확인한다.

역개요를 확인한 뒤 실제 본문을 처음부터 읽는다. 문장마다 자연스러워도 전체 흐름에서는 불필요한 부분이 있을 수 있다. 문장·문단·섹션을 각각 빼 보는 삭제 실험으로 반복, 부가 설명, 독립적인 자료 소개, 불필요한 방어 문장을 찾는다. 중요한 반증과 조건은 보존하고, 원고에서 뺀 내용을 각주나 부록에 모두 옮기는 방식으로 분량을 되살리지 않는다.

남은 주장과 인용을 다시 맞춰 보고 참고문헌을 실제 사용한 자료에 맞게 정리한다. 고정된 인용 번호나 서식이 있다면 변경 범위를 확인한다. 독자·매체·분량, 화자의 일관성, 1인칭 대명사, 도입에서 제기한 질문과 결말의 대응도 함께 점검한다. 줄이는 과정에서 이해에 필요한 설명까지 사라지지 않았는지 확인한다.

### 최종 판정

- **통과:** 각 부분의 역할이 필요하고, 독자의 시선이 이어지며, 근거와 분량이 적절하다. 요청한 결과물을 전달한다.
- **수정:** 필요한 내용이지만 설명·전제·순서·근거가 부족하다. 문제가 생긴 구성 또는 집필 단계로 돌아간다. 고친 뒤에는 영향을 받은 앞뒤와 전체 흐름을 다시 읽는다.
- **삭제:** 없어도 중심 전개가 유지되고 중복이나 곁가지에 그친다. 실제로 제거한 뒤 남은 부분을 다시 검수한다.

요청한 단계의 결과물을 전달한다. 최종 원고를 요청받았다면 원고와 필요한 출처를 중심으로 전달한다. 계획표·삭제 기록·검수표를 요청 없이 모두 덧붙이지 않는다. 수정안 제시를 공개 게시나 기존 글 덮어쓰기의 승인으로 간주하지 않는다.
